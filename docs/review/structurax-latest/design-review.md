StructuraX wave4 sap-design review (read-only)
Date: 2026-10-15
Scope: crates/sap-design wave4 changes and docs/reconstruction/design-wave4.md. No source edits.
Validation: `cargo test -p sap-design` passes (23 unit tests, 0 failures). Passing tests do not resolve the formula defects below; the H3 integration test repeats the implementation's equation.

Findings

1. AISC H3-6 interaction is wrong for both Box and Pipe, and currently underestimates combined shear. In `crates/sap-design/src/steel.rs:1345-1351`, both section types use linear axial + linear M2/M3 and `(max(V2/Vc2,V3/Vc3)+T/Tc)^2`. The supplied AISC manual `target/reconstruction/aisc36010.txt:5583-5607` specifies for Box: linear P and M terms, then `(V3/Vc3 + V2/Vc2 + T/Tc)^2`; for Pipe it specifies linear P, squared individual flexural ratios, and the same sum of both shear ratios plus torsion. Thus the max at line 1348 is not conservative when both shears are nonzero, and Pipe also needs squared bending terms. Example with normalized V2=.10, V3=.20, T/Tc=.50: the box shear term should be `.8^2=.64`; implementation gives `.7^2=.49`. The test at `crates/sap-design/src/lib.rs:1027-1032` only tests Box and calculates its expected value using the same `max` rule, so it locks in the mismatch. `design-wave4.md:18-21` overclaims H3-6 as a general equation. Add separate Box/Pipe hand substitutions and compare each demand term independently.

2. Rectangular-HSS torsional constant uses the wrong dimensions when flange and web thickness differ. `crates/sap-design/src/steel.rs:1124-1130` sets `t=min(tw,tf)` then computes `2*(B-t)*(H-t)*t - correction`. The supplied manual at `target/reconstruction/aisc36010.txt:5188-5192` gives `2*(bf-tw)*(d-tf)*min(tw,tf) - correction`. For B=6, H=10, tw=.25, tf=.50, manual C is about 27.2522 in^3; implementation is about 27.9709 in^3 (about 2.6% high). The wave4 box regression uses equal .5-in thicknesses (`lib.rs:980-984`), so it cannot catch this. The HSS slenderness at `steel.rs:1136` similarly forms one `h/t` from max dimension and minimum thickness; the manual says consider the maximum depth/thickness and width/thickness ratio (`aisc36010.txt:5211-5215`), which requires matching each flat to its corresponding wall thickness. This can spuriously reject/penalize unequal-wall sections.

3. EC3 `As3` is treated as code shear area despite being the analysis shear-deformation area. `crates/sap-design/src/shear.rs:8-10` explicitly distinguishes `as3` from EC3 `Av`, but `compute_ec3_minor_shear` then accepts any positive `sec.as3` as Av at lines 42-106 for all supported families. This silently makes result depend on the section-constructor/analysis value rather than EC3 6.2.6(3) section geometry. The tests expose the bypass: the I and Pipe cases zero `as3` to force hand-coded geometry (`lib.rs:936-952`), while Box uses its constructor's `as3=2*t2*tf` as the expected EC3 area (`lib.rs:940-945`). The generic `As3` shortcut should be removed or explicitly validated as a separately supplied EC3 Av; otherwise compute the shape-specific code area or reject the shape. The claimed support for all seven non-rectangular shape families is not independently demonstrated by the tests (only I, Box, and Pipe are invoked here).

4. Concrete M2 functionality and “biaxial” reinforcement are not established by the new regression. The M2 branch in `concrete.rs:854-880` sizes an axis-swapped rectangular section and folds those areas into the same `as_top`/`as_bot` output using `max`. This result cannot distinguish main-face reinforcement from side-face reinforcement when both M2 and M3 act. The wave4 regression supplies nonzero M2 (`lib.rs:1087-1089`) but asserts only shear reinforcement/status (`1106-1134`); it never checks that M2 changes or correctly sizes reinforcement for either ACI or EC2. The documentation at `design-wave4.md:24-28` should not present concrete minor-axis flexure / biaxial behavior as accepted until there are independent M2 calculations and an output contract that represents the required reinforcement by face, or the implementation explicitly limits itself to isolated M2 checks.

No additional concrete algorithm defect was independently established in this bounded review. The above findings are enough to block claims of verified wave4 parity as written; the package's green test result reflects current expected outputs, not independent confirmation of these cases.
