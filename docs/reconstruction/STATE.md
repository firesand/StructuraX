## GUI frame loads; concrete framing types; steel design overwrites (2026-11-13)

- **GUI loads**: the Loads tab assigns frame point loads and trapezoidal (partial, triangular) distributed loads, as forces or moments, by relative or absolute distance, in the direction chosen for frame loads. Every selected frame is validated before any is changed; "replace" acts per kind (point loads, distributed loads). The v11 module beams 3.1 to 3.3 are rebuilt through these functions in the workflow tests and give the printed reactions.
- **Concrete framing type**: `FrameObj::concrete_framing` (Sway Special, Sway Intermediate, Sway Ordinary, Non-Sway), default Sway Special as in SAP2000 (its default seismic design category D). For ACI beam design, Special requires the positive design moment at each end to be at least one half of the negative one and both design moments at every section to be at least one quarter of the largest end moment (ACI 318-14 18.6.3.2); Intermediate uses one third and one fifth (18.4.2.2). The rule set follows the vendor's concrete frame design manual. This reproduces the continuous-beam document's bottom steel (64.47 mm2) and leaves the vendor's ACI 318-14 Example 001 unchanged (2.37 in2). **The default changes existing beam designs wherever a beam has end moments.** Capacity-based shear, column and joint provisions of these framing types are not implemented, and the GUI control says so.
- **Steel design overwrites**: `FrameObj::steel_overwrite` stores the unbraced length ratios, K factors, Cb and sway flag that were a library-only argument; design reads them, and the API (`cDesignSteel::set_overwrite`) and the GUI write them. With an unbraced length ratio below 1 and no Cb given, Cb is computed within each unbraced segment and the smallest governs. The vendor's AISC 360-05 Example 001 passes for all three unbraced lengths (378.750, 307.124 and 94.377 kip-ft with its Cb values; 378.750, 306.657 and 94.218 with automatic Cb, its independent values).
- **The ebook's steel beam ratio 0.201 is reproduced only with the flange braced**, now through the stored overwrite and with W30X99 table properties (0.2011). The default stays at lateral-torsional buckling over the unsupported length (0.413 for that beam): the vendor's steel design manual specifies that default, and the vendor's own example above shows the reduction at full length in a plane-frame model like the ebook's (its file has active degrees of freedom UX, UZ, RY). The document's 0.201 is therefore not what SAP2000's documented default gives for an unbraced 10 m beam. Following the same manual, Cb is 1.0 when an unbraced length is set longer than the member, and a stored overwrite that is not a positive number stops the design.
- **Persistence**: both settings are S2K extension columns on the frame connectivity row, written only when not default; native synthesis refuses a model that carries either, instead of dropping it. Native import always yields the defaults (the vendor's design-overwrite sections are not read).
- **API**: `cDesignConcrete::set_framing_type`, `cDesignSteel::set_overwrite`; neither needs an unlocked model, and each clears only its design results.
- Integrated checks: **478 portable tests / 494 with local vendor fixtures, plus slow ignored tests (52 suites)**, strict workspace Clippy, **83/83** selected reference checks.
- **Not done**: the GUI was exercised through its workflow functions and the headless render test, not by hand; no section database ships, so a GUI user still needs one to get W30X99 table properties; design preferences (phi factors, seismic design category) remain absent.

## Remaining high-priority limits

Nonlinear link constitutive families beyond `Gap`, `Hook`, `Damper`, and `PlasticWen` (multi-linear elastic/plastic, rubber/friction/triple-pendulum isolators, bilinear and friction-spring dampers), Wen deformation reversals inside a single load case, displacement control with load reduction or a generalized monitored displacement, large-displacement corotational frame/shell kinematics, mixed cable-frame/shell/solid assemblies, and `MovingLoad` / `SteadyState` / `Psd` / `Hyperstatic` case types remain unsupported. General viscous damping on free massless coordinates outside Maxwell damper elements requires DAE treatment; exact link fixed constraints, end-offset station kinematics, and nonlinear Wilson-theta Maxwell integration remain partial or guarded. Named-coordinate three-angle ordering needs vendor comparison. Native SDB export (`pack_model_to_native_sdb`) rejects unrepresented assignments and incomplete source laws; unmodeled native tables still have no general export implementation, and generated `.sdb` files have not been opened inside a running Windows SAP2000 v19 executable. Code design remains partial for full EC3 lateral-torsional/local buckling, concrete torsion, ERW/SAW thickness overwrites, auto-select sections, and generated code combinations. Broader GUI/API coverage, full tutorial desktop interaction, and licensed vendor-runtime differential execution remain unvalidated.

Frame hinges, tendons, line/area/solid springs, frame added mass, area auto-mesh options beyond a plain N x N mesh, link gravity loads, advanced link axes and several load types remain unmodeled; native import records them and analysis refuses the affected cases (`unmodeled-source.md`, which also lists what that pass does not cover). The modal history types take no modal damping and have no mode truncation. Frame insertion points and automatic frame subdivision are bounded as described in `frame-insertion-point.md` and `frame-auto-mesh.md`.
