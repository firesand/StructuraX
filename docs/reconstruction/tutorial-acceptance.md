# SAP2000 tutorial workflow acceptance map

## Reference editions and test boundary

Use the local October 2016 `extracted/files/saptutor.pdf` as the primary tutorial: it is ISO SAP102816M2 Rev. 0 and explicitly says it introduces SAP2000 Version 19 (`target/reconstruction/saptutor-extracted.txt`, lines 11–12 and 129–135). The separately supplied January 2022 `SapTutor.pdf` is a different edition whose introduction identifies Version 16; the local text comparison is `target/reconstruction/tutorial-text-diff.txt`. Use that copy only to cross-check workflow concepts, not to define a v19 acceptance result.

The v19 tutorial itself selects AISC 360-05/IBC2006 and generates eight default steel design combinations (printed pages 2-41–2-42). This reconstruction offers AISC 360-10 and Eurocode 3. Therefore, use the tutorial as a sequence and modeling-workflow reference; do not compare code-specific design ratios or generated combinations as though they were the same configuration.

**The full tutorial workflow has not been accepted at runtime.** The separate default-model smoke test did run the native GUI, complete 26-member steel design, and display ratios (see `validation-wave1.json`); it does not establish this tutorial workflow. Status below distinguishes source availability from headless application/API tests. See `gui-wave2.md`, `editing-wave2.md`, `solver-wave2.md`, and `application-wave3.md` for implementation and test scope. Wave 3 adds case/function editors and checked preservation diagnostics; it does not complete tutorial desktop acceptance. “Ready to test” means the core operation is present; it does not mean a user completed the workflow or that SAP2000 v19 results matched. Tests should run the reconstruction GUI/API and inspect its resulting model and errors. This source audit did not launch the vendor application.

## Thirteen tutorial steps

| Step | Tutorial task | Source status | Acceptance check and present gap |
|---|---|---|---|
| 1 | Begin model; define material, frame sections, and auto-select list | **Partial** | GUI now edits validated isotropic steel/concrete/no-design materials, imports PRO sections, creates custom I sections, and assigns existing frame sections. Material save/reopen and invalid-edit atomicity are tested. Auto-select lists and design-driven section selection remain absent. |
| 2 | Draw frame objects; assign end releases; divide frames; save | **Implemented subset; tested** | GUI/API expose six-DOF end releases and equal frame division. Loaded prismatic division preserves tip displacements and reactions to 1e-9; releases and assignments survive S2K. Offsets, eccentricity, cables, nonprismatic sections and patterned temperatures are explicitly rejected by division. Tutorial interaction remains pending. |
| 3 | Assign pinned restraints to two joints | **Ready to test** | Select two joints, assign translation restraints, and inspect all six restraint flags before/after save/reopen. GUI has pinned/fixed/roller/free presets; API has six-DOF `set_restraint` (`gui.rs:522–559`; `sap-api/src/lib.rs:393–405`). No interactive result has been accepted. |
| 4 | Replicate frame objects and draw additional members | **Implemented subset; tested** | GUI/API expose linear offsets and additional copy count. Shared connectivity and assignments are preserved; incompatible coincident joints and duplicate elements fail atomically. Rotation/mirror replication is not exposed. |
| 5 | Define area sections; draw, mesh, and replicate area objects | **Partial; editing tested** | GUI defines shell sections, assigns structured quad subdivisions, and replicates selected areas through Geometry. Four-node drawing still picks the first existing area section; assign the intended section afterward. Edge-point-driven meshing and full tutorial topology acceptance remain pending. |
| 6 | Move selected objects | **Implemented subset; tested** | GUI/API translate selected joints and selected frame/area connectivity once per joint. Shared joints move connected unselected elements too, disclosed in the editor. Locked/invalid edits preserve inputs and results. |
| 7 | Assign area stiffness modifiers | **Implemented editor; tested** | GUI edits all ten section modifiers; API sets modifiers. F22=0 and property/mesh assignment survive S2K roundtrip. Section edits affect every area using that property. Tutorial-specific force comparison remains pending. |
| 8 | Define DEAD/LIVE/WIND load patterns and self-weight | **Implemented subset; tested** | GUI defines patterns, type and self-weight, and creates matching static cases. Conflicting pre-existing case definitions fail atomically. A headless egui pointer-click test creates WIND. Automatic lateral generators remain absent. |
| 9 | Assign joint forces, live roof pressure, and windward/leeward pressure | **Partial; tested** | GUI edits all six global joint force/moment components, uniform global-Z frame loads, and uniform top/bottom area pressure. Positive pressure acts into the selected face. API pressure resultants pass independent checks. Edge/patterned pressure is explicitly unsupported. Exact tutorial load directions and resultants still need acceptance. |
| 10 | Select design preferences and define load combinations | **Partial; editor tested** | GUI edits five combination types and case/combo factors with dependency-cycle checks and S2K roundtrip coverage. Code-generated combinations and design-preference editor remain absent. Tutorial AISC 360-05 is not equivalent to implemented AISC 360-10. |
| 11 | Run analysis | **Partial** | Core operations for move/replicate/divide/area mesh/pressure/combinations are now exposed and tested individually. Full thirteen-step tutorial model, exact analysis options, vendor numerical outputs and GUI interaction acceptance remain pending. |
| 12 | Graphically review analysis results | **Partial** | Select each load case and verify deformed shape, reactions, axial/shear/torsion/moment diagrams, and shell contours against reference values. GUI offers deformed shape, reactions, six frame-force diagrams, five shell contours, and limited tables; table view currently covers joint displacements/reactions rather than the tutorial’s full review (`gui.rs:584–635, 866–879, 2142–2204`). Tutorial-specific visual runtime acceptance is pending. |
| 13 | Design steel frame objects and revise selected sections | **Partial** | Run a separately specified supported design case, compare governing ratios and code settings to a matching reference, then verify any selected analysis sections. GUI can run AISC 360-10/EC3 and display ratios. It has no design-preference dialog, generated design combinations, auto-select section-list optimization, or design-to-analysis-section update. V19 tutorial’s AISC 360-05 workflow/results are not a direct numerical target (`gui.rs:638–654`; `sap-api/src/lib.rs:1246–1278`). |

## Acceptance sequence

1. Exercise steps 1–3 and 8–10 through the API to isolate model-state operations. Assert material/section values, releases, restraints, load patterns, cases, combination factors, and mutation/result invalidation.
2. Exercise the GUI-supported create/draw/save/open paths with a reduced model. Compare object counts, joint coordinates, restraints, sections, and import warnings after reopening S2K. Test private SDB only as an internal save format.
3. Exercise the implemented editing operations together on the tutorial model: frame divide/replicate/move; area meshing/replication and modifiers; patterns, pressure and combinations. Code-generated combinations, auto-select sections and other remaining gaps must stay explicit; do not manually alter serialized input to claim a completed GUI workflow.
4. Validate the solver on a supported reduced model first. Compare each load case’s displacements, reactions, frame-force stations, and shell resultants using a version-matched reference and stated tolerances. Record unsupported inputs instead of omitting them silently.
5. Validate design separately against a reference that uses AISC 360-10 or EC3. Record code, units, load combinations, station, section, demand/capacity components, and unsupported material/section/demand errors. Do not use the tutorial’s AISC 360-05 ratios as pass criteria.
6. Perform a user-operated GUI pass for visible menus, selection, drawing, save/open, errors, and plots after code-level checks pass. Record OS/display backend, model fixture hash, screenshots or interaction log, and tester/date; this is still pending.
