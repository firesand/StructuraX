# StructuraX capability scope

**Snapshot: 2026-11-15, post-parity & hardening milestones, merged with the 2026-11-12 solver and import additions (plastic Wen links, displacement control, unmodeled source data, area import, frame subdivision and insertion points) and the 2026-11-15 tutorial-video wave ([tutorial-video-wave1.md](tutorial-video-wave1.md)); the dated paragraphs below carry the later waves through the sixth (2026-11-18, [tutorial-video-wave6.md](tutorial-video-wave6.md)).** This is a scope map, not product parity or a safety certification. Historical wave notes record implementation work; the latest repair and milestone notes supersede earlier unsupported-feature bounds where explicitly tested. The machine-readable inventory is [capabilities.json](capabilities.json).

The strongest path remains selected linear and bounded nonlinear structural analyses with analytical checks. The model contains more element, case and design families than every solver/API path can execute. Imported data and enum presence are not evidence of supported physics.

## Solver

Frame, area/shell and eight-node solid formulations are present. Solid mass/weight modifiers honor zero; invalid values reject. Nonlinear static Gap/Hook and selected nonlinear histories recover reactions from actual constitutive forces. General large-displacement behavior, complete damping/constraint treatment and other nonlinear laws remain incomplete.

Cable analysis is a guarded cable-only nonlinear-static subset supporting undeformed length, horizontal tension, and target I-end tension (`target_tension_i`, verified on Example 7-003). Mixed cable-frame/shell/solid element models, cable springs/constraints, and unsupported partial/nonuniform cable loads reject instead of being silently changed. Capped frames (`tc_limits`) enforce tension/compression cutoffs under distributed span axial loads and self-weight while preserving exact static reaction equilibrium (`< 1e-10`), and reject unverified releases/offsets/geometric combinations. `TransientTerminalState` stores physical (`u`, `v`, `a`, `previous_force`), nonlinear link, and mass-orthonormal modal generalized (`modal_q`, `modal_v`, `modal_a`) states for chained direct-integration and modal `LinearHistory` restarts; nonlinear Wilson-theta Maxwell integration remains unavailable. See [solver-fixes.md](solver-fixes.md).

Plastic Wen link DOFs are supported in small-displacement nonlinear static and direct-integration history cases, and nonlinear static cases can be displacement-controlled on one monitored joint displacement. A Wen deformation that reverses inside one load case, load reduction under displacement control, generalized monitored displacements, and combinations with geometric nonlinearity, cables, member limits or Wilson-theta integration reject. Other link families still reject. See [solver-wen.md](solver-wen.md).

Frame hinges are supported in nonlinear static cases for user-defined uncoupled deformation-controlled properties (P, V2, V3, T, M2, M3), with saved states, Accel and Mode loads and a pushover curve; the model must consist of frames only and the hinges must be its only nonlinearity. Coupled, fiber, automatic and force-controlled hinges, strength loss of P, V and T hinges, reversal after yield and hinges in time history are refused. The traversal of strength loss is a reconstruction checked on CSI Example 1-026 only. See [tutorial-video-wave2.md](tutorial-video-wave2.md).

Since 2026-11-18 ([tutorial-video-wave6.md](tutorial-video-wave6.md)): a nonlinear static case with P-Delta runs with frame hinges when the hinges are at element ends, every case of the chain has the same geometric setting and no frame has a directly specified P-Delta force; other combinations stay refused. A Modal or linear static case may use the stiffness at the end of a nonlinear static case of a hinged model while no hinge has yielded there. A hinge case that stops before its target keeps its states with the status "not finished" (a project choice; the status words are the vendor's), the cases that need it "could not start", and the analysis succeeds. Results that changed: a moment hinge at end I of an element with a geometric stiffness, and every Modal or linear case after a nonlinear static case without P-Delta, which no longer gets a geometric stiffness (v19 Analysis Reference p. 411). Interacting P-M3 hinges, automatic hinges and a computed yield moment remain refused: neither the v19 nor the v24 material states a rule for them. Also since that date: frame forces of time-history cases include the member loads, their base reactions include restrained joints generated by area meshing, a time-history load stores whether it is a load pattern or a ground acceleration (an input that does not say and could be either is refused), and a combination with a contributor that has no results has no result itself and is listed with the reason. Since 2026-11-19: a load case and a load combination may not share a name (refused at import, table editing, analysis and design); a combination with a time-history contributor is withheld with a reason, because only one step of a history is stored for forces and reactions and the extrema over time are not computed; a time-history pattern may hold joint forces and frame distributed and point loads, by one rule shared by the solver and the case definition check, and every other load type in it is refused by name; native export writes a history load by its meaning, so a legacy acceleration name and the aliases X, Y, Z export; and the iteration of a P-Delta case with hinges is judged in force units, which makes its results independent of the units of the model.

Since 2026-11-19, after an outside audit ([audit-2026-11-19.md](audit-2026-11-19.md), ledger D85 to D149): results changed in steel design (pipe interaction with torsion, the slender-element factor Q, double angles and double channels, EC3 Class 3 sections), concrete design (column shear with axial force and at 45° under EC2, the minor-axis magnifier, compression steel of doubly reinforced beams, the EC2 strut angle, the ACI minimum eccentricity), the solver (V13 and V23 of thin shells, reactions through constraints, response-spectrum directions by SRSS, area loads in a continued history, cable length from the self-weight shape, fixed link degrees of freedom) and import (rebar yields and section rebar from native files, four type tags of the older section libraries, the vendor's S2K table of area modifiers). Under EC3 a member with compression and a moment is checked by EN 1993-1-1 6.3.3(4) with the factors of Annex B (Method 2) for I sections with equal flanges, boxes and pipes; the standard is the source there, by the user's decision, since neither vendor manual prints the factors (D89). Newly refused by name: under EC3 other shapes with compression and a moment, and Class 4 sections; I sections with unequal flanges; pipes beyond the vendor's slenderness limit; response-spectrum cases with two functions in one direction, a directional combination other than SRSS, a modal combination other than CQC, SRSS or Absolute, or a load at an angle; member limits under axial span loads of both signs; a native diaphragm split per level. In a second part the same day: AISC compression of tees, double angles, channels and double channels includes flexural-torsional buckling (D128); AISC flexure of pipes, boxes, channels, tees and double angles has its local and lateral-torsional limit states (D129); rectangular concrete beams are designed for torsion under ACI 318-14 and Eurocode 2 as the vendor manuals print it (D130; the values are in the results, not yet displayed, D146; the printed Eurocode 2 rule gives torsion stirrups that do not shrink with the torsion when the shear is above V_Rd,c, built as printed and not checked in the vendor program; on a 3D test frame every beam took the rule and the transverse steel rose 2.4 times, D148). Newly refused by name with it: under AISC a single angle in compression or bending, a box with a slender flange in bending, a channel whose web is beyond the compact limit in major bending; torsion on a concrete beam that is not rectangular. A refused member is recorded with its reason and the other members are designed (D127); errors of the whole run (code name, combinations, forces) still stop it. For doubly symmetric steel I-sections with noncompact webs and dimensions consistent with sharp-corner plates, major-axis bending uses the AISC F4 limits. A bending check that needs unrecorded fillet geometry or fabrication data gives a named refusal. With zero major-axis demand, other checks proceed and the result identifies the unavailable capacity (D142). ACI and EC2 beam design requires a rectangular section. Other beam shapes receive a per-member error and the design continues on supported members (D144).

History types (`LinearHistory`, `NonlinearHistory`) are integrated directly over all degrees of freedom with Rayleigh damping, and a nonzero modal damping ratio on them is refused, unless a `LinearHistory` case names a modal case: then the modes of that case are superposed with one constant damping ratio, exactly for piecewise-linear loads. Proportional or interpolated modal damping, link damping in modal form, an initial case and nonlinear modal history are not implemented. The native N x N area auto-mesh (when its options match the solver's meshing), area added mass and object-level area modifiers are imported; see [area-import.md](area-import.md), which also records the corrected native shell-type, element-type and incompatible-modes codes and the published checks behind them. Axisymmetric-solid sections, plane sections with incompatible modes, and buckling or P-Delta with area or solid elements are refused. Frame hinges, tendons, line/area/solid springs, frame added mass, frame auto-subdivision, area auto-mesh options the model cannot express, frame joint offsets, link gravity loads, advanced link local axes and several load types are not modeled. Native import records them as unmodeled source data (83 of the 336 corpus files) and analysis refuses the affected cases until an entry is explicitly discarded. Since 2026-11-17 the same holds for a Ritz starting load of a native Modal case that is neither a load pattern nor an acceleration (the vendor's starting vectors for link degrees of freedom; the Modal cases of Examples 6-006, 6-007, 6-010, 6-011a and 6-011b are refused as imported) and for periodic and nonlinear modal (FNA) histories. What that pass does not cover is listed in [unmodeled-source.md](unmodeled-source.md).

Automatic frame subdivision for analysis (a number of segments, or at the joints lying on a frame) is analyzed, with results reported per frame object and only for the model's joints. It is refused with cables, member tension/compression limits, end length offsets, a segment count together with a joint on the span, and area-mesh joints on the frame; subdivision at crossings and by maximum segment length is not modeled. A buckling case with no initial case buckles under its own scaled load patterns. Span moment loads and span loads on non-prismatic members were corrected at the same time. See [frame-auto-mesh.md](frame-auto-mesh.md). A frame insertion point (cardinal point other than the centroid, or joint offsets) with stiffness transformation is modeled as rigid arms for equal offsets across the member, doubly symmetric shapes and linear static cases, and refused otherwise; see [frame-insertion-point.md](frame-insertion-point.md). Frame M2 is reported in the SAP2000 sign convention (it had the opposite sign).

The mass of a model can come from element mass, additional mass and load patterns (one mass source per model). ASCE 7-10 automatic seismic loads are computed from that mass with entered site coefficients and importance factor; site-class lookup and the program-calculated period are refused, and no other code or edition is implemented. Since 2026-11-17 the eccentric moment on diaphragms about Z is applied (ratio × width perpendicular to the load × storey force, or an overwrite distance per pattern and diaphragm); the sense of a positive eccentricity is this project's choice, because the lateral loads manual prints none. Ritz cases start from their listed loads with cycle limits and dynamic participation targets, and every modal case reports static and dynamic load participation. Since 2026-11-17 a Ritz case returns at most as many modes as there are mass degrees of freedom (Analysis Reference p. 373), and its projection switches from the stiffness form to a flexibility form where the stiffness form would lose its digits (stiff members, penalty diaphragms); before, such models could give more modes than mass degrees of freedom, periods above the exact ones or a failure. In the flexibility form the static participation of a starting load is not exactly 100 % (at most 7.2e-6 off in the stiffest test model); the switch is a project threshold. The factorization works on the matrix profile and larger Eigen cases use subspace iteration with a Sturm check; matrices are still stored dense, which bounds models to a few thousand joints.

Shell stress output was corrected on 2026-11-16 and differs from earlier versions: the reported top-face stresses are now those of the top face (`F/t − 6M/t²`, CSI Analysis Reference Eqns. 2; before, the bottom face's), stress resultants under shell temperature loads no longer count free thermal strain as stress (CSI Examples 2-013 and 2-014), the temperature gradient load has the vendor's sign and is imported from native files, von Mises and principal values of linear combinations are recomputed from the combined components, a combination reports shell, solid or link results only for objects every contributing case has them for, and the base reaction includes the supports an area mesh creates. Shell temperature loads on three-joint areas, with joint patterns, or on a section without the stiffness they act on (including plane and axisymmetric-solid sections), and response-spectrum directions other than U1 to U3, are refused. The stored top-face von Mises value of a multi-valued combination was combined field by field; since 2026-11-17 it is stored as 0 in both rows, the tables print "n/a" and the display refuses it. See [tutorial-video-wave3.md](tutorial-video-wave3.md).

Result display was extended on 2026-11-17. Shell resultants and stresses can be shown by component (the vendor form's fourteen resultants and nine stresses) and face (top, bottom, visible, maximum, minimum, absolute maximum) in display units that leave the model locked; they are derived from the stored element-centre resultants, so there is no Gauss-point extrapolation and no averaging at joints, and principal, von Mises, bottom-face and face-extreme values are refused for multi-valued results (envelope, SRSS, absolute and range combinations, response-spectrum cases), as are quantities a plate, membrane or plane-stress section does not have and every quantity of a plane-strain or axisymmetric-solid section (the display of plane sections is not done; the stored forces of plane-strain areas are recovered with the plane-strain relation since the repairs described in the next paragraph). The deformed shape has displacement contours on areas, a joint read-out in joint-local axes and animation through result steps. Plot functions include the absolute acceleration of modal time histories (relative acceleration plus the case's ground acceleration; the vendor's formula is not documented), several traces, a horizontal function, a time range and named sets for the session; velocity and reaction are not recorded. Modal results changed on that date: participation factors and mass ratios are in global directions at joints with local axes (before, joint-local components were summed as if global, and response-spectrum results inherited the error), and the rotational ratios RX, RY, RZ are about the centre of mass for every model (CSI Analysis Reference pp. 339, 376-378; before, only rotational inertia at joints was counted). The deformed shape of joints with local axes and the handedness of the 3D view were corrected. The corpus holds nothing for AISC 360-16 or ASCE 7-16. See [tutorial-video-wave4.md](tutorial-video-wave4.md).

Solver results changed on 2026-11-17 with the repairs of the fifth wave; [tutorial-video-wave5.md](tutorial-video-wave5.md) has the numbers and the references. Combinations: every multi-valued combination (additive with a response-spectrum or other multi-valued case, envelope, range, SRSS, absolute) stores a maximum and a minimum (Analysis Reference pp. 351-353); the API and the tables return a Max row and then a Min row. Before, one value was stored: an envelope kept the value of larger magnitude and a range was added linearly. An additive combination of single-valued cases is unchanged bitwise. Derived fields of a multi-valued result are 0. Of the API's multi-valued options only the envelope option is implemented. Response-spectrum cases store no area results, so a combination with one has none.

Area materials, same date: orthotropic constants are used by shells, plates, membranes and plane sections (before, E1 and u12 as isotropic; CSI Example 2-015). Plane-strain areas have the plane-strain recovery, a stored S33 and anti-plane shear stiffness on U3, so U3 of such a model must be supported. The material angle of an area section turns only the material (before, also the output axes; this reverses the rule of the fourth wave). Stiffness modifiers scale the coupling terms by the root of their product in stiffness and in recovery alike. Plane and axisymmetric-solid sections have no drilling stiffness. An orthotropic law that is not positive definite and a temperature load with unequal in-plane expansion coefficients are refused. The eight-node solid builds its orthotropic compliance differently from the manual's printed equation (found, not changed).

Frame end offsets, same date: the rigid-zone factor shortens only the bending and shear length; a full moment or shear release makes its offset rigid in that plane (Analysis Reference pp. 130-131). Span loads and self weight act over the full length, and the part on a rigid arm goes to its joint. A non-prismatic section varies over the clear length. A rigid arm adds `P × arm` to the geometric stiffness, which changes P-Delta and buckling results of members with rigid arms. Output stations run from support face to support face, so a member with offsets has no station at relative distance 0 or 1; design takes the first and the last station as the ends of the member (for the end minimums of special and intermediate concrete frames) and measures Cb between them. Not implemented: the manual's reduction of offsets to a clear length of 1 %, the mass of the end zones, automatic subdivision and hinges on such members. Further repairs of that date: constraints act in global directions at joints with local axes (the Local type stays joint-local). Direct-integration histories take zero before the first point of a time function and refuse a missing function. The message for an unstable structure names the joint and direction; mechanisms that pass the pivot test are still accepted. Station deflections include the kink of an interior M2 or M3 hinge.

## Design

AISC closed-section torsion uses distinct Box/Pipe interaction equations and unequal-wall HSS dimensions. EC3 local-3 design implements EN 1993-1-1 §6.2.6(3) plastic shear areas across 10 standard section profiles (`Rectangular`, `I`, `Channel`, `DbChannel`, `T`, `Angle`, `DblAngle`, `Box`, `Pipe`, `Circle`) and interaction checks of P, V2, V3, M2 and M3; torsion is not designed under EC3 (refused for Box and Pipe, noted for other shapes, vendor manual 2.2.1), and EC3 compression with bending follows 6.3.3(4) with the Annex B factors for I, box and pipe sections and is refused for other shapes (G71); comprehensive lateral-torsional/local buckling and unmodeled shapes still reject. Concrete beam minor-axis flexure (`M2`) under ACI 318-14 and Eurocode 2 reports side-face longitudinal reinforcement via `ConcreteDesignResult.as_side` (a StructuraX extension: SAP2000 designs beams for major-axis flexure only, ACI 318-14 manual p. 3-28). Existing column PMM and supported shear checks remain partial, and concrete torsion is neither designed nor refused (D130). See [design-fixes.md](design-fixes.md).

Concrete frames carry a framing type (default Sway Special, as in SAP2000): ACI beam design applies the end and span moment-strength rules of Special (one half, one quarter) and Intermediate (one third, one fifth) frames; their capacity-based shear, column and joint provisions are not implemented. Steel members carry stored design overwrites (unbraced length ratios, K factors, Cb, sway); the default lateral-torsional length is the unsupported member length, checked against the vendor's AISC 360-05 Example 001. Both are settable in the GUI and the API and persist in S2K only.

Auto Select section lists are analyzed with a list member and designed for the lightest member within the demand/capacity limit (AISC 360-10 manual rules; the median choice for an even list is this project's). Default LRFD and ASD design combinations follow the same manual, with stated differences where a load type is absent and for response-spectrum cases. Seismic design category, steel seismic framing types and second-order preferences are not implemented; AISC 360-16 is absent.

Design of a multi-valued combination changed on 2026-11-17. Each state of the combination (its Max row, its Min row, each contributing state of an envelope) is designed with its own moment diagram and its own Cb, and the design adds the permutations of the maxima and minima of the forces a check combines: P, M2 and M3 for the steel axial-flexure interaction and the concrete column check, the shears as well for Eurocode 3 section 6.2.8, torsion and shears as well for the closed-section torsion interaction (that last mask has no test). For concrete beam torsion the design pairs torque with major shear and the axial force (ACI) or major bending moment (EC2). The vendor's design manuals ask for such sub-combinations (AISC 360-10 manual section 2.4, ACI 318-14 manual section 2.1); that one permutation takes the same choice at every station is this project's choice. Before, only the positive sense of a multi-valued contributor was designed. Concrete beams are designed per state without permutations. Sub-combinations per time step of a history and the corresponding-values option of moving loads are not implemented. Concrete design is refused when neither the section's rebar material nor the concrete gives a rebar yield stress (before, 60 ksi was assumed). Single-valued combinations and plain cases are unchanged bitwise.

## Interchange

S2K semantic support remains table-selected with source/opaque preservation and conservative edit reconciliation. Native source-byte copy and inventory are distinct from synthesized model export. Native export validates references, nonlinear completeness, source-preservation boundaries and represented-data roundtrips before writing. Recognized handwritten S2K formatting does not block export; unknown tables/columns and unrepresented assignments still do. Material colors, 21-term `TYSpring` coupled/local springs, orthotropic `S_Material`, `S_CableData` (`3/5/8`), 3x3 joint `local_axes_matrix` (`S_POINTOBJECTS`), independent shear-rebar yield `fys != fy` (`S_MaterialPropertiesRebar`, except for Rebar materials, whose `m_RebarProps.m_fy` is their own yield: a Rebar material with `fys != fy` is refused on native export), `project_info` (`S_ProjectInfo`), and coordinate system grids (`S_GUIDE`) all roundtrip losslessly. All native saves use exclusive creation and verified disk readback. Class-version tags come from the local corpus; internal parsing and self-roundtrips do not establish SAP2000 runtime acceptance. See [format-fixes.md](format-fixes.md).

Native synthesis refuses a model that carries unmodeled source data, so 46 corpus files that were previously written without that data are now refused (44 before 2026-11-17; Example 6-005a joined them with its nonlinear modal history, and on 2026-11-19 Example 1-024 with a response-spectrum case combined by the NRC 10 percent method, D141), and the two Example 1-026 files are refused for their frame hinges, which the native writer has no records for (281 accepted native projections, down from 329). S2K keeps the entries in an extension table.

The mass source, automatic seismic loads, Ritz controls, mode superposition, Auto Select state and steel design preferences are kept by S2K through reconstruction extension tables and columns; native synthesis refuses a model that carries them, and native import does not read the vendor's records for them, with one exception since 2026-11-17: the modal case of a history is read from a native file (a transient linear history is then superposed on its modes; CSI Example 6-001 matches its published values with its ramp samples attached) and written for a linear history. The seismic eccentricity overwrites are kept by S2K in an extension table and refused by the native writer.

## Application and API

Grid definition and editing, quick draw on grid regions, radial replicate and extrusion, reversal of area local 3, curved frames, selection by section and diaphragm assignment are model commands with GUI windows; assignments that a radial copy cannot reproduce exactly are refused. Plan and elevation views at a grid line, window selection, previous selection and mouse drawing tools (quick draw on the grid of a plane view, frames and areas through picked points) exist since 2026-11-16, together with a 2D frame template on a custom grid, division of frames with a length ratio, breaking frames at intersections, a material library read at run time from the vendor's files (not shipped), import of several section-file shapes at once and an in-program file chooser. Areas keep the solver's limit of four joints; snapping is to joints and grid intersections only. All of these windows and tools were tested through command functions and headless renders with synthetic pointer input, and have no `cSapModel` facade. See [tutorial-video-wave3.md](tutorial-video-wave3.md).

Since 2026-11-17: export of an animation as an uncompressed AVI (the steps of a history or of saved static states, or the cycles of a mode), written by the project's own writer and rasteriser without an encoder; a read-out of the loads on an object; a "Grid Only" start; an I section with unequal flanges; an automatic scale and a title that names the mode or step for the deformed shape; Max and Min rows in the result and database tables and both curves in the frame diagram; a rebar material choice for concrete sections; a Messages window with the session's status messages. Not offered: a compressor, a cyclic video of a plain deformed shape, files above 1 GiB. On that date the real program was run for the first time, by an agent on a private virtual display with synthetic input and screenshots, through the four parts of the tutorial video; it found defects that tests had not (numbers printed as "0.0", the old model's display kept after Open, an unreadable cut status line), which were repaired. No person has used the windows, and the items no one looked at (among them window resizing and the file chooser behind Browse) are listed in [tutorial-video-progress.md](tutorial-video-progress.md), D17.

The GUI exposes selected geometry, load, material, section, link/cable, case/function, database-table and result workflows, including `ConcreteDesignResult.as_side` reporting. The typed Rust OAPI surface validates solid geometry and temperature accumulation before mutation and includes a 21-method `cCableObj` facade (with strict namespace isolation from `cFrameObj`) and a 19-table transactional `cDatabaseTables` facade (`GetTableForDisplayArray`, `SetTableForEditingArray`, `ApplyEditedTables`). It is not a Windows COM server. Full tutorial interaction and native Windows/macOS acceptance remain pending. See [application-fixes.md](application-fixes.md).

## Acceptance still required

- Independent numerical tests for each newly supported combination, with input provenance, units and tolerances.
- Licensed vendor-runtime comparisons, including exported-file acceptance and critical assignment comparisons.
- Wider structural/design code coverage and complete result/state contracts.
- Full desktop workflows and target-platform installation/runtime checks.

The latest integrated test counts and exact source fingerprint belong in the dated validation record, not in the capability status labels. Passing the selected reference suite does not establish correctness outside its checked cases.
