# SAP2000 v19 reconstruction capability inventory

**Snapshot: 2026-10-15 (Wave 4).** This inventory includes wave-4 3D solid elements, catenary cables and member tension/compression limits, nonlinear direct-integration time-history and state continuation, schema-driven native SDB export, expanded steel/concrete design checks, and API/CLI extensions; see the wave notes for exact tested scope. Historical source line ranges may have shifted. It is a capability map, not a parity percentage or a statement that the complete SAP2000 v19 product has been reconstructed.

The machine-readable row set is [capabilities.json](capabilities.json). It contains 22 feature rows: 4 implemented with relevant tests present (`frame-linear-static`, `solid-elements`, `cables-and-member-limits`, `native-sdb-preservation`), 17 implemented partially, 1 unsupported (`other-case-types`), and 0 unknown. These are counts of inventory rows, not mutually exclusive product features or coverage percentages. “Implemented-tested” means a test or fixture workflow exists; it does not claim that a full vendor comparison passed.

## What the source currently supports

The data model is broad. It stores point, frame, area, solid, and link objects; 34 frame section kinds; load, case, combination, material, constraint, and dynamic-function families. That breadth does not map directly to executable behavior. The solver assembles frame, area, and 8-node 3D isoparametric solid stiffness (including Taylor-Beresford-Wilson 9 incompatible bending modes, degenerate wedges/tetrahedra, self-weight, `Face 1..6` surface pressure, uniform temperature loads, and `SolidResult` stress/nodal-force recovery), adds joint springs and selected multipoint constraints, and solves 3D elastic catenary cables (Peyrot & Goulois 1979) and frame axial tension/compression limits (`tc_limits`). Links use oriented six-deformation stiffness/damping assembly with shear offsets; linear cases use effective linear properties, while nonlinear static and direct-integration time-history (`NonlinearHistory` / `NonlinearDynamic`) cases solve `Gap`, `Hook`, and Maxwell-series `Damper` links (`k` in series with `c * |v|^exp`) with `initial_case` state continuation. Incomplete imported constitutive data cannot enter nonlinear analysis, and `PlasticWen`, `Isolator1`, and `Isolator2` remain explicitly rejected until verified.

The most complete analysis path is linear static analysis of frame, area/shell, and solid models, with recovered reactions, frame-force stations, area results, and solid stresses. Nonlinear static/P-Delta (including catenary cables and T-C limits), modal, buckling, response-spectrum, linear time-history, and nonlinear direct-integration time-history paths exist and are verified against vendor `.sdb` benchmarks (`Example 1-001`, `5-001`, `5-002`, `5-005`, `6-003`, `6-004`, `6-005`, `7-001`, `7-002`). Newmark, HHT-alpha, and Wilson-theta integrators have numerical tests; HHT/Wilson still need broader SAP2000 v19 reference-trace validation. Additional load case families (`MovingLoad`, `SteadyState`, `Psd`, `Hyperstatic`) are rejected in preflight. Named Cartesian load systems are normalized in an analysis-only copy, including projected frame loading; original assignments survive. Three-angle ordering remains a documented reconstruction convention pending vendor comparison. General viscous damping on free massless coordinates outside Maxwell damper elements remains unsupported.

The design crate has checked AISC 360-10 LRFD/ASD, EC3, ACI 318-14, and EC2 entry points. AISC local-3 shear checks I, Channel, Double Channel, T, Angle, Double Angle, Box, Pipe, Rectangular, Circle, General, and SD sections, and contributes to governing ratio selection. The checked steel entry point rejects Aluminum and ColdFormed materials. EC3 local-3 shear now supports Rectangular, I, Channel, Double Channel, T, Box, Pipe, and Circle sections, including high-shear bending reduction when $|V_3| / V_{\text{pl},3,\text{Rd}} > 0.5$ under pure $V_3$ or combined $V_3 + M_2$. AISC 360-10 closed-section (`Box` and `Pipe`) torsional strength $T_c$ (Section H3.1) and combined Torsion + Shear + Flexure + Axial interaction (Eq. H3-6 when $|T_r| > 0.20 T_c$) are implemented; missing wall thickness is rejected explicitly. The model has no ERW/SAW or thickness-reduction/overwrite metadata, so Box/Pipe formulas assume the supplied thickness and area are already design values. Concrete beam and column checks in ACI 318-14 and Eurocode 2 now evaluate both major-axis (`V2`) and minor-axis (`V3`) shear $(A_v/s)_2$ and $(A_v/s)_3$ as well as beam minor-axis flexure (`M2`), while nonzero concrete torsion (`|T| > 1e-9`) remains explicitly rejected.

S2K semantic support remains table-selected with original source and opaque table/column preservation, unique-owner reconciliation after supported edits, and explicit errors for ambiguity or unknown dimensions following unit conversion. Native SDB stream inventory traverses all 64 schema-known top-level sections and preserves exact compressed source bytes across all 336 local SDB files (`inspect-sdb` and `copy-native-sdb`). SDB model import now extracts `NLLINKPROPARRAY.m_param` (`5 x 6 = 30` `f64` nonlinear parameters), single-joint grounded links (`m_SingleJoint`), parametric Sine functions (`FUNCSHUNARRAY`), and `CABLEPROPERTYARRAY` / `S_CableData`. Schema-driven native `cBinaryStream` serialization (`pack_model_to_native_sdb`, `save_native_sdb_file`, `cFile::save_native_sdb`, and CLI `export-native-sdb`) writes genuine SAP2000 v19 native `.sdb` streams that pass `inspect_native_sdb` 100% to EOF, alongside the existing `RUST_SAP2000_S2K_V19` private container (`save_sdb_file`).

The API is a Rust facade around a subset of model, file, point, frame, cable, area, solid, link, property, load/case/combo, result, and design operations (`cPropSolid`, `cSolidObj`, `cFrameObj` cable/T-C limits, `cAnalysisResults::solid_stress`, `cFile::save_native_sdb`). It is not a COM/OAPI server. The GUI exposes transactional move/replicate/divide, materials, frame sections, releases, area section modifiers/mesh, patterns, joint/frame/pressure loads, combinations, analysis cases and dynamic functions. Headless egui input/render and save/reopen tests cover these paths; the full tutorial desktop flow remains unaccepted.

## Highest-impact gaps to resolve

1. **Extend remaining nonlinear constitutive and case families.** Implement or retain explicit rejection for `PlasticWen`, `Isolator1`, `Isolator2`, large-displacement corotational frame/shell kinematics, and `MovingLoad` / `SteadyState` / `Psd` / `Hyperstatic` case types.
2. **Broaden design interaction and code overwrite coverage.** Add ERW/SAW design-thickness and code overwrite metadata for steel sections, multi-axis EC3 combined shear + biaxial bending + axial interaction, and concrete torsion design.
3. **Validate native SDB export in a licensed SAP2000 v19 runtime.** `pack_model_to_native_sdb` satisfies the 64-section v19 `cBinaryStream` schema and round-trips through `inspect_native_sdb` and `extract_sdb_to_model`, but opening exported `.sdb` files in the native Windows SAP2000 v19 executable remains to be verified.
4. **Expand traceable vendor verification coverage.** `sap2000-rs verify` now checks 60 reference comparisons across frame, shell, modal, buckling, P-Delta, thermal, solid (`5-001`), nonlinear link/damper history (`6-003`, `6-005`), and catenary cable (`7-001`, `7-002`) benchmarks; expand coverage across the remaining 336-file vendor `.sdb` corpus.
5. **Build end-to-end workflows on top of verified primitives.** Reconcile API contracts with CSI's installed OAPI type library and complete GUI visualization/editing for solids, cables, and nonlinear time-history traces.

## Ordered acceptance checklist

Use the [JSON checklist](capabilities.json) as the machine-readable acceptance list. Work in this order because later results depend on earlier model and import correctness:

1. Freeze the local fixture manifest. Record v19 provenance, hashes, input version, units, expected table inventory, reference values, tolerances, and whether each expected value comes from CSI output or independent hand calculation.
2. Import representative SDB and S2K files; compare object counts and high-risk assignments (units, restraints, local axes, sections, releases, load patterns/cases, combinations, and analysis options). Any omitted table or field must appear in the import report.
3. Round-trip supported S2K tables and compare normalized input/output tables. Keep native SDB inventory/source-byte copy and native model projection as separate checks; compare both against fixtures. Do not count the private Rust SDB container as vendor interchange.
4. Compare one frame at a time for axial, both shear directions, torsion, both moments, releases, offsets, temperature, self weight, and coordinate transforms; then compare multi-frame assemblies and reaction equilibrium.
5. Compare triangle and quad membrane/plate/shell examples, then auto-meshed areas. Test each shell type and reject higher-order connectivity until the solver accepts it.
6. Validate all supported analysis cases against vendor examples. Add negative cases for nonlinear history/dynamic, moving load, PSD, steady state, hyperstatic, large displacement, initial-state use, unsupported integration settings, solids, cable properties, unsupported nonlinear link laws/combinations, undefined named load systems, general massless damping, and unsupported constraints.
7. Compare modal periods/shapes/participating mass, buckling factors, response-spectrum combinations, and Newmark history traces with exact input data and documented tolerances.
8. Compare AISC LRFD/ASD and EC3 design examples by section family and interaction case. Include local shear 2/3, closed-section torsion, axial tension/compression, biaxial bending, slender elements, LTB, and invalid section/material/code inputs. Confirm that open-section torsion remains ignored where the CSI AISC manual specifies it.
9. Compare ACI and EC2 beam and column examples including flexure, each shear direction, biaxial demand, column slenderness, reinforcement layout, and failure status.
10. Audit each exposed API operation against the version-matched CSI OAPI type library, object browser, or installed API help; contract tests should cover argument order, names, defaults, return codes, error reporting, units, result invalidation, and unsupported calls. Use `csirefer.pdf` for analysis-method conventions and benchmarks.
11. Exercise GUI workflows end to end and verify that import omissions, analysis errors, unsupported design demands, and failed exports are visible and do not leave stale results displayed.
