# StructuraX capability scope

**Snapshot: 2026-11-15, post-parity & hardening milestones, merged with the 2026-11-12 solver and import additions (plastic Wen links, displacement control, unmodeled source data, area import, frame subdivision and insertion points) and the 2026-11-15 tutorial-video wave ([tutorial-video-wave1.md](tutorial-video-wave1.md)).** This is a scope map, not product parity or a safety certification. Historical wave notes record implementation work; the latest repair and milestone notes supersede earlier unsupported-feature bounds where explicitly tested. The machine-readable inventory is [capabilities.json](capabilities.json).

The strongest path remains selected linear and bounded nonlinear structural analyses with analytical checks. The model contains more element, case and design families than every solver/API path can execute. Imported data and enum presence are not evidence of supported physics.

## Solver

Frame, area/shell and eight-node solid formulations are present. Solid mass/weight modifiers honor zero; invalid values reject. Nonlinear static Gap/Hook and selected nonlinear histories recover reactions from actual constitutive forces. General large-displacement behavior, complete damping/constraint treatment and other nonlinear laws remain incomplete.

Cable analysis is a guarded cable-only nonlinear-static subset supporting undeformed length, horizontal tension, and target I-end tension (`target_tension_i`, verified on Example 7-003). Mixed cable-frame/shell/solid element models, cable springs/constraints, and unsupported partial/nonuniform cable loads reject instead of being silently changed. Capped frames (`tc_limits`) enforce tension/compression cutoffs under distributed span axial loads and self-weight while preserving exact static reaction equilibrium (`< 1e-10`), and reject unverified releases/offsets/geometric combinations. `TransientTerminalState` stores physical (`u`, `v`, `a`, `previous_force`), nonlinear link, and mass-orthonormal modal generalized (`modal_q`, `modal_v`, `modal_a`) states for chained direct-integration and modal `LinearHistory` restarts; nonlinear Wilson-theta Maxwell integration remains unavailable. See [solver-fixes.md](solver-fixes.md).

Plastic Wen link DOFs are supported in small-displacement nonlinear static and direct-integration history cases, and nonlinear static cases can be displacement-controlled on one monitored joint displacement. A Wen deformation that reverses inside one load case, load reduction under displacement control, generalized monitored displacements, and combinations with geometric nonlinearity, cables, member limits or Wilson-theta integration reject. Other link families still reject. See [solver-wen.md](solver-wen.md).

Frame hinges are supported in nonlinear static cases for user-defined uncoupled deformation-controlled properties (P, V2, V3, T, M2, M3), with saved states, Accel and Mode loads and a pushover curve; the model must consist of frames only and the hinges must be its only nonlinearity. Coupled, fiber, automatic and force-controlled hinges, strength loss of P, V and T hinges, reversal after yield and hinges in time history are refused. The traversal of strength loss is a reconstruction checked on CSI Example 1-026 only. See [tutorial-video-wave2.md](tutorial-video-wave2.md).

History types (`LinearHistory`, `NonlinearHistory`) are integrated directly over all degrees of freedom with Rayleigh damping, and a nonzero modal damping ratio on them is refused, unless a `LinearHistory` case names a modal case: then the modes of that case are superposed with one constant damping ratio, exactly for piecewise-linear loads. Proportional or interpolated modal damping, link damping in modal form, an initial case and nonlinear modal history are not implemented. The native N x N area auto-mesh (when its options match the solver's meshing), area added mass and object-level area modifiers are imported; see [area-import.md](area-import.md), which also records the corrected native shell-type, element-type and incompatible-modes codes and the published checks behind them. Axisymmetric-solid sections, plane sections with incompatible modes, and buckling or P-Delta with area or solid elements are refused. Frame hinges, tendons, line/area/solid springs, frame added mass, frame auto-subdivision, area auto-mesh options the model cannot express, frame joint offsets, link gravity loads, advanced link local axes and several load types are not modeled. Native import records them as unmodeled source data (83 of the 336 corpus files) and analysis refuses the affected cases until an entry is explicitly discarded. What that pass does not cover is listed in [unmodeled-source.md](unmodeled-source.md).

Automatic frame subdivision for analysis (a number of segments, or at the joints lying on a frame) is analyzed, with results reported per frame object and only for the model's joints. It is refused with cables, member tension/compression limits, end length offsets, a segment count together with a joint on the span, and area-mesh joints on the frame; subdivision at crossings and by maximum segment length is not modeled. A buckling case with no initial case buckles under its own scaled load patterns. Span moment loads and span loads on non-prismatic members were corrected at the same time. See [frame-auto-mesh.md](frame-auto-mesh.md). A frame insertion point (cardinal point other than the centroid, or joint offsets) with stiffness transformation is modeled as rigid arms for equal offsets across the member, doubly symmetric shapes and linear static cases, and refused otherwise; see [frame-insertion-point.md](frame-insertion-point.md). Frame M2 is reported in the SAP2000 sign convention (it had the opposite sign).

The mass of a model can come from element mass, additional mass and load patterns (one mass source per model). ASCE 7-10 automatic seismic loads are computed from that mass with entered site coefficients and importance factor; site-class lookup, the program-calculated period and eccentric diaphragm moments are refused, and no other code or edition is implemented. Ritz cases start from their listed loads with cycle limits and dynamic participation targets, and every modal case reports static and dynamic load participation. The factorization works on the matrix profile and larger Eigen cases use subspace iteration with a Sturm check; matrices are still stored dense, which bounds models to a few thousand joints.

## Design

AISC closed-section torsion uses distinct Box/Pipe interaction equations and unequal-wall HSS dimensions. EC3 local-3 design implements EN 1993-1-1 §6.2.6(3) plastic shear areas across 10 standard section profiles (`Rectangular`, `I`, `Channel`, `DbChannel`, `T`, `Angle`, `DblAngle`, `Box`, `Pipe`, `Circle`) and multi-axis ($P, V_2, V_3, M_2, M_3, T$) interaction checks; comprehensive lateral-torsional/local buckling and unmodeled shapes still reject. Concrete beam minor-axis flexure (`M2`) under ACI 318-14 and Eurocode 2 reports side-face longitudinal reinforcement via `ConcreteDesignResult.as_side`. Existing column PMM and supported shear checks remain partial, and concrete torsion remains unsupported. See [design-fixes.md](design-fixes.md).

Concrete frames carry a framing type (default Sway Special, as in SAP2000): ACI beam design applies the end and span moment-strength rules of Special (one half, one quarter) and Intermediate (one third, one fifth) frames; their capacity-based shear, column and joint provisions are not implemented. Steel members carry stored design overwrites (unbraced length ratios, K factors, Cb, sway); the default lateral-torsional length is the unsupported member length, checked against the vendor's AISC 360-05 Example 001. Both are settable in the GUI and the API and persist in S2K only.

Auto Select section lists are analyzed with a list member and designed for the lightest member within the demand/capacity limit (AISC 360-10 manual rules; the median choice for an even list is this project's). Default LRFD and ASD design combinations follow the same manual, with stated differences where a load type is absent and for response-spectrum cases. Seismic design category, steel seismic framing types and second-order preferences are not implemented; AISC 360-16 is absent.

## Interchange

S2K semantic support remains table-selected with source/opaque preservation and conservative edit reconciliation. Native source-byte copy and inventory are distinct from synthesized model export. Native export validates references, nonlinear completeness, source-preservation boundaries and represented-data roundtrips before writing. Recognized handwritten S2K formatting does not block export; unknown tables/columns and unrepresented assignments still do. Material colors, 21-term `TYSpring` coupled/local springs, orthotropic `S_Material`, `S_CableData` (`3/5/8`), 3x3 joint `local_axes_matrix` (`S_POINTOBJECTS`), independent shear-rebar yield `fys != fy` (`S_MaterialPropertiesRebar`), `project_info` (`S_ProjectInfo`), and coordinate system grids (`S_GUIDE`) all roundtrip losslessly. All native saves use exclusive creation and verified disk readback. Class-version tags come from the local corpus; internal parsing and self-roundtrips do not establish SAP2000 runtime acceptance. See [format-fixes.md](format-fixes.md).

Native synthesis refuses a model that carries unmodeled source data, so 44 corpus files that were previously written without that data are now refused, and the two Example 1-026 files are refused for their frame hinges, which the native writer has no records for (283 accepted native projections, down from 329). S2K keeps the entries in an extension table.

The mass source, automatic seismic loads, Ritz controls, mode superposition, Auto Select state and steel design preferences are kept by S2K through reconstruction extension tables and columns; native synthesis refuses a model that carries them, and native import does not read the vendor's records for them.

## Application and API

Grid definition, quick draw on grid regions, radial replicate and extrusion, reversal of area local 3, curved frames, selection by section and diaphragm assignment are model commands with GUI windows; assignments that a radial copy cannot reproduce exactly are refused. There is no mouse drawing on grids, no plane view at a level and no file chooser. The windows added on 2026-11-15 were tested headless, not by hand, and have no `cSapModel` facade.

The GUI exposes selected geometry, load, material, section, link/cable, case/function, database-table and result workflows, including `ConcreteDesignResult.as_side` reporting. The typed Rust OAPI surface validates solid geometry and temperature accumulation before mutation and includes a 21-method `cCableObj` facade (with strict namespace isolation from `cFrameObj`) and a 19-table transactional `cDatabaseTables` facade (`GetTableForDisplayArray`, `SetTableForEditingArray`, `ApplyEditedTables`). It is not a Windows COM server. Full tutorial interaction and native Windows/macOS acceptance remain pending. See [application-fixes.md](application-fixes.md).

## Acceptance still required

- Independent numerical tests for each newly supported combination, with input provenance, units and tolerances.
- Licensed vendor-runtime comparisons, including exported-file acceptance and critical assignment comparisons.
- Wider structural/design code coverage and complete result/state contracts.
- Full desktop workflows and target-platform installation/runtime checks.

The latest integrated test counts and exact source fingerprint belong in the dated validation record, not in the capability status labels. Passing the selected reference suite does not establish correctness outside its checked cases.
